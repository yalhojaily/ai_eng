1. BM25: tf-idf with two corrections

BM25 has been the standard word-matching ranking function for about thirty years and is still the baseline every new retriever is compared with. It keeps idf and repairs two faults in raw term frequency.

Saturation. In tf-idf a word occurring twenty times counts twenty times as much as one occurrence. But a page that mentions dual twenty times is not twenty times more about the dual than a page that mentions it once; after the first few mentions, more add little. BM25 makes the contribution level off. The parameter k1 sets how quickly.

Length normalisation. Long documents contain more of every word simply by being long. BM25 discounts term frequency in documents longer than average and boosts it in shorter ones. The parameter b sets how strongly, from 0 (ignore length) to 1 (full correction).

score(term, doc) = idf(term) × tf × (k1 + 1)
                              ─────────────────────────────────────────
                              tf + k1 × (1 − b + b × doclen / avglen)

See the saturation

Experiments. Set b to 0: the three curves merge, because length no longer matters. Set k1 to 0: the score ignores how often the word appears, only whether it does. Raise k1 to 3 and the curves approach the dashed straight line of plain tf-idf. The usual defaults, k1 near 1.2 and b near 0.75, are a good start.

2. Lexical and semantic similarity

Two texts are lexically similar when they share word forms, and semantically similar when they share meaning. The two usually go together, which is why word matching works at all. The interesting cases are where they part:

PairLexicalSemantic
plural / more than onenonehigh
river bank / bank loanhighlow
the drug is safe / the drug is not safevery highopposite
كتاب / وكتابهاnone, as stringsthe same word

The last row is different in kind. The two strings are the same lexical item wearing different clitics. That is not a meaning problem. It is a morphology problem, and for word matching to work in Arabic it has to be solved before any scoring happens.

3. Teaching word matching some morphology

English search engines get by with lowercasing and sometimes stemming, chopping endings so that writes and writing meet at writ. Arabic needs more, because so much is attached to the word and because the script allows several spellings of the same thing. A typical light normalisation pipeline:

  1. Remove vowel marks and the stretching character (tatweel). كِتابٌ becomes كتاب.
  2. Unify letter variants. The forms of alef أ إ آ become ا; final ى becomes ي; ة becomes ه. Writers are inconsistent about all three.
  3. Strip common prefixes: the conjunction و, the article ال, and prepositions fused to it.
  4. Strip common suffixes: possessive pronouns and regular plural and dual endings.
Try it · 2

Normalise, then match

Read the last rows. الكُتُب, "the books", does not match: Arabic's commonest plurals change the word's internal pattern (Lesson 1), which no amount of chopping at the edges can undo. And مكتبة (library) now equals مكتب (office): the normaliser merged two different words. Then try the query ولد (boy) with the document word ولدها (her boy): the first letter of the word itself is mistaken for “and” and stripped.

Every normalisation step trades recall for precision: more matches found, some of them wrong. Light stemming is a deliberate, modest position on that trade. Full lemmatisation, mapping each word to its dictionary form with a morphological analyser or the annotator you built in Phase 2, is more accurate and far more expensive. Whichever you choose, apply the identical function to documents at indexing time and to queries at search time.

4. Hybrid search

Run both retrievers and combine their results. The reason is not that two is more than one. It is that their errors are nearly independent: BM25 misses paraphrases and finds exact terms, dense retrieval does the reverse. A passage found by either is a candidate, and a passage ranked highly by both is very likely relevant.

The difficulty is combining them. BM25 scores are unbounded positive numbers that depend on the collection. Cosine similarities sit between −1 and 1. Adding them is meaningless, and rescaling them is fragile.

5. Reciprocal rank fusion

The robust solution ignores scores and uses only ranks. Each retriever gives each document a rank; the document's fused score is the sum, over retrievers, of

1 / (k + rank)          with k commonly set to 60

First place contributes 1/61, second 1/62, and so on. A document missing from a list contributes nothing from that list. The constant k damps the advantage of the very top positions, so that being ranked 3rd by both retrievers beats being ranked 1st by one and absent from the other.

6. In practice

  • Retrieve deep, fuse, then cut. Take perhaps the top 50 from each retriever, fuse, and keep the top 10 or 20 for the next stage.
  • Hybrid is the sensible default. It rarely loses to either component alone and often beats both. Lesson 16 gives you the numbers to confirm that on your data.
  • Keep BM25 honest. It is only as good as its tokeniser and normaliser. For Arabic, most of BM25's quality is decided in section 3.

Lab: BM25, normalisation and fusion

Time: 90 minutes. pip install rank-bm25. Load the chunks and embeddings you saved in Lesson 14.

import re
from rank_bm25 import BM25Okapi

DIACRITICS = re.compile(r"[ً-ْٰـ]")
PREFIX = re.compile(r"^(وال|بال|كال|فال|لل|ال|و)")
SUFFIX = re.compile(r"(ها|هم|هن|كم|نا|ات|ون|ين|ان|ه|ي)$")

def normalize_ar(w):
    w = DIACRITICS.sub("", w)
    w = re.sub("[أإآ]", "ا", w).replace("ى", "ي").replace("ة", "ه")
    for rule in (PREFIX, SUFFIX):
        stripped = rule.sub("", w)
        if len(stripped) >= 3:
            w = stripped
    return w

def tokenize(text):
    out = []
    for w in re.findall(r"\w+", text.lower()):
        out.append(normalize_ar(w) if re.search(r"[؀-ۿ]", w) else w)
    return out

bm25 = BM25Okapi([tokenize(t) for t in texts])          # texts from Lesson 14

def bm25_search(query, k=50):
    scores = bm25.get_scores(tokenize(query))
    return list(np.argsort(-scores)[:k])

def dense_search(query, k=50):
    return list(np.argsort(-(E @ model.encode(query, normalize_embeddings=True)))[:k])

def rrf(rankings, k=60, top=10):
    scores = {}
    for ranking in rankings:
        for rank, doc in enumerate(ranking, start=1):
            scores[doc] = scores.get(doc, 0) + 1 / (k + rank)
    return sorted(scores, key=scores.get, reverse=True)[:top]

def hybrid_search(query, top=10):
    return rrf([bm25_search(query), dense_search(query)], top=top)
