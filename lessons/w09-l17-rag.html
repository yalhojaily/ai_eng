Generating answers with citations

Retrieval finds the passages. Now a model has to answer from them, and only from them, and show where each statement came from. Getting the passages into the prompt is easy. Getting the model to stay inside them, and proving that it did, is the engineering.

Answer to last lesson's question. You cannot detect it by looking at the answer alone: a wrong answer from memory reads as fluently as a right one from the sources. You have to require the model to tie each statement to a passage, then check the tie. That requirement, and the check, are this lesson.

RAG gives a model knowledge it was never trained on: your documents, last week's changes, private data. Compared with relying on the model's memory it has three advantages. The knowledge can be updated by editing files, with no training. Answers can point to their sources. And the model has less reason to invent, since the facts are in front of it.

"Less reason" is not "no reason". A model can still ignore the passages and answer from memory, blend the two, or stretch a passage to cover something it does not say. An answer that goes beyond its sources is called unfaithful or ungrounded, and when the invented content is false, a hallucination.

2. What "supported by the source" means

Semantics has a precise notion for this. A text entails a claim if anyone who accepts the text must accept the claim. The text contradicts the claim if accepting the text means rejecting the claim. Otherwise the claim is neutral: perhaps true, but not something this text settles. Deciding which relation holds is a standard task in NLP called natural language inference.

A faithful answer consists of claims the retrieved passages entail. The dangerous category for RAG is the third. Neutral claims are often true, sound right, and come from the model's memory. The system has no evidence for them, and you cannot tell the true ones from the false ones.

3. The generation prompt

Everything from Phase 2 applies. The parts that are particular to RAG:

[system]
Answer the question using only the passages inside <sources>.
Every sentence of your answer must be supported by a passage;
give that passage's id and the exact words that support it.
If the passages do not contain the answer, say so. Do not use
knowledge from outside the passages, even if you are confident.

[user]
<sources>
  <passage id="c1">POS tags › AUX › Copula: The copula is ...</passage>
  <passage id="c2">...</passage>
</sources>
<question>How does UD tag the copula?</question>
  • Passages are data. They sit inside tags and are described as material, exactly as the sentence was in Lesson 5. A retrieved document may contain text that reads like an instruction.
  • Each passage has an ID. Short and stable, so that citations are easy to write and to check.
  • Passages first, question last, following Lesson 7's ordering advice.
  • The escape route is stated. A model given no permitted way to say "not found" will find something to say.

4. Citations that code can check

A citation written as a footnote in prose is decoration. Ask instead for structured output (Lesson 4): a list of sentences, each with the ID it rests on and a verbatim quote from that passage. The quote is the key. A model can attach a plausible ID to anything, but it cannot produce an exact quote that is not there, and a program can check exact quotes without any model at all.

5. Knowing when not to answer

Some questions have no answer in the corpus. The correct output then is a clear "the sources do not say", and a system that can produce it is far more trustworthy than one that always answers. Three things make abstention work:

  • The prompt allows it and the schema has a place for it, such as an answerable field that comes before the answer.
  • The retriever's scores are used: if even the best reranker score is low, skip generation and abstain in code.
  • The eval set contains unanswerable questions, so that wrongly answering and wrongly abstaining are both counted.

The two errors trade against each other like precision and recall. A system tuned never to invent will sometimes refuse questions it could have answered. Decide which is worse for your use, and measure both.

6. Evaluating the whole thing

A RAG system has two components and can fail in either, so it gets measured in layers:

QuestionMeasured by
Was the needed passage retrieved?recall@k (Lesson 16)
Are citations real?the citation gate, in code
Does each sentence follow from its quote? (faithfulness)a validated model judge (Lesson 11)
Is the answer right? (correctness)comparison with a reference answer, by judge
Did it abstain when it should?counts on the unanswerable items

Faithfulness and correctness are different. An answer can be faithful to a retrieved passage that happens to be outdated, and so be wrong. It can also be correct from memory while citing nothing, and so be unfaithful. You want both, and when you must choose in a system built on your documents, faithfulness comes first: it is the property that lets a user check you.

Checkpoint

Lab: answers you can check

Time: 2 hours. Use the retrieval stack from Lesson 16 and call_json from Lesson 8.

ANSWER_SCHEMA = {
    "type": "object",
    "properties": {
        "answerable": {"type": "boolean"},
        "sentences": {"type": "array", "items": {
            "type": "object",
            "properties": {
                "text":  {"type": "string"},
                "cite":  {"type": "string"},
                "quote": {"type": "string"},
            },
            "required": ["text", "cite", "quote"], "additionalProperties": False}},
    },
    "required": ["answerable", "sentences"], "additionalProperties": False,
}

def squash(s):
    return " ".join(s.split())

def check_citations(answer, passages):
    """passages: dict id → text. Returns a list of problems (empty if fine)."""
    problems = []
    for n, s in enumerate(answer["sentences"], start=1):
        if s["cite"] not in passages:
            problems.append(f"sentence {n} cites unknown passage {s['cite']!r}")
        elif len(s["quote"].split()) < 3:
            problems.append(f"sentence {n}: the quote is too short to be evidence")
        elif squash(s["quote"]) not in squash(passages[s["cite"]]):
            problems.append(f"sentence {n}: the quote does not appear in {s['cite']}")
    return problems

def answer(question, top=5, max_retries=1):
    hits = rerank(question, rrf([bm25_search(question), dense_search(question)], top=50), top=top)
    passages = {f"c{n}": texts[i] for n, i in enumerate(hits, start=1)}
    sources = "\n".join(f'<passage id="{k}">{v}</passage>' for k, v in passages.items())
    user = f"<sources>\n{sources}\n</sources>\n<question>{question}</question>"
    for attempt in range(max_retries + 1):
        out = call_json(RAG_SYSTEM, user, ANSWER_SCHEMA, "answer")
        problems = check_citations(out, passages) if out["answerable"] else []
        if not problems:
            return out, passages
        user += "\nYour previous answer was rejected: " + "; ".join(problems)
    raise ValueError("no verifiable answer")
  1. Write RAG_SYSTEM from section 3. Ask ten questions your corpus can answer. Read every answer against its quotes.
  2. Write five questions the corpus cannot answer, some of them about things the model surely knows from training (for example, the capital of a country). Does it abstain, or answer from memory?
  3. Log how often the gate rejects a first attempt, and why.
  4. Build a faithfulness judge: given one sentence and its quote, PASS if the quote entails the sentence. Label twenty sentence-quote pairs yourself first, then report kappa (Lesson 11).
  5. Remove the instruction to use only the passages. Rerun step 2. What changes?
  6. For three wrong or refused answers, diagnose the stage: retrieval, ranking, generation or abstention.
