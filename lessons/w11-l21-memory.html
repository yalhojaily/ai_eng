Memory and planning

A short agent run takes care of itself. A long one drowns in its own history and forgets what it set out to do. Two disciplines keep long runs on course: deciding what to remember, and deciding what to do before doing it.

1. The growth problem

In Lesson 19 you saw the context grow at every step. Put numbers on it. If each step adds about 1,000 tokens of tool output and reasoning, step 30 sends about 30,000 tokens, and the whole run has billed the sum of 1,000 + 2,000 + … + 30,000: about 465,000 input tokens. The total grows with the square of the number of steps. And well before the window is full, quality declines, because the few facts that matter are buried.

The remedy is compaction: at intervals, replace old history with something much shorter that preserves what matters.

2. Four places to keep things

WhereWhat it isUse it for
The contextthe live message listthe current step's working material
A summaryold messages replaced by a short account, written by a modelkeeping the thread of a long run
Notesa structured record the agent writes to through a tool, outside the contextfindings, decisions, evidence IDs: things that must survive exactly
Retrievalpast material stored in an index and fetched when relevant (Phase 4)large histories, knowledge across many runs

Summaries are lossy, and what they lose is chosen by a model. So anything that must not be lost should not depend on a summary. That is the role of notes: when the agent establishes something, it records it at once, as a claim with the IDs of its evidence. After compaction the notes are put back into the context in full. A research agent with good notes can forget nearly everything else.

Notes also solve a quieter problem. Deep into a run, agents lose track of the original question. Re-inserting the goal and the notes after every compaction puts the task back in front of the model, at the end of the context, where Lesson 7 says it is used best.

3. This week's linguistics: register

A plan for studying a word needs to know how language varies. People do not write one English, or one Arabic. A news report, a novel and a research paper differ systematically, in grammar as well as vocabulary. Linguists call a variety associated with a situation of use a register, and the differences are measurable. Fiction is full of personal pronouns and past-tense narration. Academic prose prefers abstract nouns built from verbs (discussion, measurement), which are called nominalisations, and passive constructions (was run, is discussed). News is dense with reported speech.

Arabic adds a further axis: the formal written standard and the regional spoken varieties differ so much that linguists describe the situation with a special term, diglossia.

4. Planning

An agent that only ever asks "what next?" tends to follow whatever its last result suggested. A plan gives it a destination. Two styles:

  • Plan, then execute. The first step produces an explicit plan, a short list of sub-questions; later steps work through it. Predictable and easy to inspect, but brittle if the plan was wrong.
  • Interleaved. The agent plans a little, acts, and reconsiders, as in Lesson 19's trace. Adaptive, but it can drift.

The useful middle is a plan the agent may revise. Ask for the plan as structured output, store it in the notes, have the agent tick items off, and allow it to add or drop items with a stated reason. The plan then doubles as a progress report that you can read while the agent runs.

5. Sub-agents: memory by delegation

Some tasks split into parts that do not need each other's details. An orchestrator agent can hand each part to a sub-agent: a fresh loop with its own empty context, a narrow instruction and the same tools. The sub-agent may use fifty thousand tokens exploring fiction; it returns a ten-line summary with evidence IDs, and only that enters the orchestrator's context.

This is compaction by design, and the parts can run in parallel (Lesson 8). The price is the boundary problem from Lesson 8: a sub-agent knows only what its instruction says. Brief it like any newcomer (Lesson 5): the goal, what to return, in what form, and what "done" means.

6. Working rules

  • Shrink at the source first. Smaller tool results (Lesson 20) beat any amount of clever compaction.
  • Write findings down when they are made, with evidence IDs, in notes that survive compaction.
  • Compact on a trigger, such as a token threshold, and put the goal, plan and notes back afterwards.
  • Keep recent steps verbatim. The last few results are what the agent is working with.
  • Measure. Compaction can drop something that mattered. Run the same task with and without it and compare outcomes, not only token counts.

Checkpoint

Lab: notes, a plan, and compaction

Time: 2 hours. Extend the agent from Lessons 19 and 20.

NOTES = {"plan": [], "findings": []}

def set_plan(steps):
    NOTES["plan"] = [{"step": s, "done": False} for s in steps]
    return {"ok": True, "plan": NOTES["plan"]}

def complete_step(index, note=""):
    if not 0 <= index < len(NOTES["plan"]):
        return {"error": f"No step {index}. The plan has {len(NOTES['plan'])} steps, numbered from 0."}
    NOTES["plan"][index]["done"] = True
    return {"ok": True, "remaining": [p["step"] for p in NOTES["plan"] if not p["done"]]}

def save_finding(claim, evidence_ids):
    known = {sid for sid, _, _ in INDEX}
    bad = [e for e in evidence_ids if e not in known]
    if bad:
        return {"error": f"Unknown line IDs {bad}. Use IDs exactly as returned by concordance."}
    NOTES["findings"].append({"claim": claim, "evidence": evidence_ids})
    return {"ok": True, "findings_so_far": len(NOTES["findings"])}

def count_tokens(messages):
    return sum(len(str(m)) for m in messages) // 4          # rough, good enough for a trigger

def compact(messages, keep_last=6):
    """Replace old history with the goal and the notes; keep the most recent messages."""
    system, question = messages[0], messages[1]
    recent = messages[-keep_last:]
    while recent and (recent[0]["role"] if isinstance(recent[0], dict) else recent[0].role) == "tool":
        recent = recent[1:]                                 # never start on an orphaned tool result
    memo = {"role": "user", "content":
            "Earlier steps were removed to save space. Your notes so far:\n"
            + json.dumps(NOTES, ensure_ascii=False, indent=1)
            + "\nContinue from the plan. The original question is repeated above."}
    return [system, question, memo] + recent

  2. In the loop, call compact whenever count_tokens(messages) exceeds a threshold such as 6,000.
  3. Give it a broad task: "Describe how light is used across all five genres, with evidence." Run it with and without notes and compaction. Compare steps, total input tokens, and the quality of the final answer.
  4. Read the plan the agent wrote. Did it stratify by genre? Did it follow its plan? Did it ever revise it?
  5. After a compaction, does the agent repeat work it had already done? If so, what was missing from the notes?
