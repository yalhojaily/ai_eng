Answer to last lesson's question. The provider's server runs the whole loop: tokenize, predict, sample, append, repeat. You never see the probabilities. You send text and a few numbers that shape the sampling, and you get tokens back.

1. The request is a small JSON document

Nearly every model provider accepts the same basic shape, usually called the chat completions format. It has three parts:

  • model: which model to run.
  • messages: the text, as a list of turns. Each turn has a role and content.
  • Parameters: numbers that control generation, such as temperature and max_tokens.

There are three roles. system sets standing instructions and is written by you, the developer. user is the person's input. assistant is what the model said earlier. Before the model sees any of it, the server flattens the whole list into one long token sequence with special marker tokens between turns. Roles are a convention the model was trained on, not separate channels.

2. The model remembers nothing

  
This is the fact that surprises most developers. The model keeps no state between requests. A chat application feels like a conversation only because, on every turn, the application sends the entire history again, with the new message at the end.

3. Sampling: language as a probability distribution

  
Psycholinguists have a classic experiment, the cloze task: show people a sentence with a gap and record what they fill in. "I would like a cup of ___." Most say tea or coffee; a few say water; almost nobody says joy. The proportion giving each answer is that word's cloze probability. Humans carry a probability distribution over what comes next, and reading slows down measurably at unexpected words.

  
A language model's output is the same object. How unexpected a word is has a name, surprisal, and the average surprisal of a distribution is its entropy, measured in bits. Low entropy: the next word is nearly certain. High entropy: many continuations are plausible. Sampling parameters reshape this distribution before one token is drawn.

  
    
    
  • temperature sharpens (below 1) or flattens (above 1) the distribution. At 0 the top token always wins.
    • 
    
  • top_p (nucleus sampling) keeps only the most likely tokens whose probabilities add up to p, and discards the long tail entirely.
    • 
    
  • max_tokens is a hard cap on output length. It does not make the answer concise; it cuts it off.
    • 
    
  • stop is a list of strings that end generation when produced.
    •

Experiments. (1) Set temperature to 0.1 and draw: how many distinct words? (2) Set it to 2.0 and draw: did joy or tokens appear? (3) Keep temperature at 2.0 but lower top_p to 0.8. The tail is cut, so you get variety without nonsense. That combination is why top_p exists.

  


  
Which settings to use depends on the job. For extraction, classification and anything you will evaluate, use a low temperature: you want the same answer each time. For brainstorming or varied phrasing, go higher. Change temperature or top_p, not both at once, until you have a reason.


  
4. Streaming

  
Tokens are produced one at a time. By default the server waits until the last one and sends the whole answer. With "stream": true it sends each piece as it is generated. The total time is the same. What changes is the time to first token, which is what a person waiting actually feels.

5. What comes back

  
The response is also JSON. Three fields matter every time:


{
  "choices": [{
    "message": { "role": "assistant", "content": "A morpheme is ..." },
    "finish_reason": "stop"
  }],
  "usage": { "prompt_tokens": 27, "completion_tokens": 19, "total_tokens": 46 }
}

  
    
    
  • content: the generated text.
    • 
    
  • finish_reason: why generation ended. stop means the model finished on its own. length means it hit max_tokens and the answer is cut off. Always check it.
    • 
    
  • usage: the token counts you are billed for. Input and output are priced separately, and output usually costs several times more per token.
    •

6. Habits to form now

  
    
    
  • Keys live in environment variables. Never in source code, never in a repository. A leaked key is someone else spending your money.
    • 
    
  • Check finish_reason. A truncated answer looks fine until it is parsed.
    • 
    
  • Log usage from day one. You cannot control a cost you never measured.
    • 
    
  • Expect variation. Even at temperature 0, outputs can differ slightly between runs. Do not write tests that demand identical strings.
    • 
    
  • Expect failure. Requests time out and get rate-limited. Wrap calls with a retry that waits longer each time.
    •

Lab: talk to a real model

  
Time: 60 minutes. Setup: the lab uses OpenRouter, which exposes many providers' models behind one API in the standard chat format, called through the widely used openai client library. What you learn transfers to any provider.


pip install openai
export OPENROUTER_API_KEY="sk-or-..."   # from openrouter.ai/settings/keys

  
Choose any inexpensive chat model from openrouter.ai/models and paste its ID into MODEL.


import os, time
from openai import OpenAI

client = OpenAI(
    base_url="https://openrouter.ai/api/v1",
    api_key=os.environ["OPENROUTER_API_KEY"],
)
MODEL = "provider/model-name"   # replace with a real ID

def ask(messages, **params):
    return client.chat.completions.create(model=MODEL, messages=messages, **params)

# --- Part A: first call ---
r = ask([
    {"role": "system", "content": "You are a concise linguistics tutor."},
    {"role": "user", "content": "What is a morpheme? One sentence."},
], temperature=0.7, max_tokens=200)
print(r.choices[0].message.content)
print(r.choices[0].finish_reason, r.usage)

# --- Part B: sampling ---
cloze = [{"role": "user", "content":
          "Fill the gap with exactly one word, nothing else: I would like a cup of ___"}]
for t in (0.0, 1.0, 1.8):
    words = [ask(cloze, temperature=t, max_tokens=5).choices[0].message.content.strip()
             for _ in range(8)]
    print(t, words)

# --- Part C: streaming ---
start, first = time.time(), None
stream = ask([{"role": "user", "content": "Explain the distributional hypothesis in 80 words."}],
             stream=True)
for chunk in stream:
    if not chunk.choices:
        continue
    piece = chunk.choices[0].delta.content
    if piece:
        first = first or time.time() - start
        print(piece, end="", flush=True)
print(f"\nfirst token {first:.2f}s, total {time.time() - start:.2f}s")
