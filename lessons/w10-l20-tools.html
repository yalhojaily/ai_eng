Designing tools a model can use well

An agent sees the world only through what its tools return. Give it clumsy tools and no prompt will save it. Most of the difference between an agent that works and one that flails is decided here, in ordinary function design.

1. Tools have a new kind of reader

You have designed functions for programs, which want complete, exact data, and interfaces for people, who want something readable. A model is a third kind of consumer. It reads like a person, pays for every token it reads, re-reads everything at every later step (Lesson 19), and acts on what it reads without being able to ask you what you meant.

So the question for every tool is the one from Lesson 5, turned around: if a capable assistant received this return value with no other explanation, could they take the right next step?

2. A lesson from corpus linguistics: count fairly

Suppose a word occurs 9 times in the news texts and 5 times in the academic texts. Is it more typical of news? You cannot say until you know how much text each contains. If the news section is twice the size, 9 against 5 is no difference at all.

Corpus linguists therefore never compare raw counts across corpora of different sizes. They report normalised frequency: occurrences per fixed amount of text, conventionally per million words. It is the first thing a student of the field learns, and exactly the kind of thing an agent will get wrong if its tool hands it raw counts.

3. Design the return value

Five properties of a good return value:

  • Bounded. Never return an unlimited amount. Cap it, and make the cap a parameter with a sensible default.
  • Honest about what is missing. "Showing 8 of 3,412" tells the agent the sample is partial and that narrowing the request is possible. Silent truncation makes it reason from a fragment as if it were the whole.
  • Already digested. Do the arithmetic in code: totals, rates, rankings. Models are unreliable at counting lines and dividing.
  • Citable. Give every item a short stable ID, so the final answer can point to its evidence and your code can check it (Lesson 17).
  • Plain. Short labelled text or compact JSON. No decoration, no fields the agent will never use.

5. Errors are messages to the agent

  
When a tool fails, the result still goes into the context and the model still reads it. A stack trace teaches it nothing. An error written as advice lets the agent correct course on the next step, which is what the retry-with-feedback pattern of Lesson 8 depends on.

6. The set of tools

  
Fewer, distinct tools beat many overlapping ones. If two tools could plausibly answer the same need, the model will sometimes choose the wrong one, and you will spend your prompt explaining the difference. Merge them, or make the boundary obvious in their names.

  
Pick the right level. Too low, such as "run this regular expression over a file", and the agent must rebuild corpus linguistics from parts, slowly and with mistakes. Too high, such as "analyse this word", and you have hidden the whole task inside one opaque call that the agent cannot steer. Aim for the operations a human expert thinks in: concordance, frequency, collocates, define.

  
Collocates deserves a note, since you will build it. The standard measure of how strongly two words attract each other is pointwise mutual information: how much more often they occur together than they would if they were independent. You met it in Lesson 2's vector builder. It has a known flaw: it gives extreme scores to pairs that occurred together once or twice by accident. Corpus tools apply a minimum count before ranking, and so must yours. A tool that returns statistical noise at the top of its list is worse than no tool.

  
Finally, watch the agent use them. Read traces. Where it calls a tool with wrong arguments, calls two tools in sequence every time, or ignores a result, the tools are telling you how they should be redesigned.

import math
from collections import Counter
from functools import lru_cache
from nltk.corpus import wordnet
from nltk.stem import WordNetLemmatizer

lemmatize = lru_cache(maxsize=None)(WordNetLemmatizer().lemmatize)   # cached: it is called a lot

def forms_match(token, word):
    t = token.lower()
    return t == word or lemmatize(t, "v") == word or lemmatize(t, "n") == word

# Index every sentence once, with a stable ID such as "news:00412".
INDEX = [(f"{g}:{i:05d}", g, sent) for g in GENRES
         for i, sent in enumerate(brown.sents(categories=g))]

def concordance(word, genre=None, limit=8):
    word = word.lower()
    if genre is not None and genre not in GENRES:
        return {"error": f"Unknown genre {genre!r}. Valid genres: {', '.join(GENRES)}."}
    hits = [(sid, " ".join(s)) for sid, g, s in INDEX
            if (genre is None or g == genre) and any(forms_match(t, word) for t in s)]
    if not hits:
        return {"total": 0, "note": f"No occurrences of {word!r}"
                + (f" in {genre}" if genre else "") + ". Check the spelling, or try another genre."}
    return {"total": len(hits), "showing": min(limit, len(hits)),
            "note": "Sample only; narrow by genre or raise limit to see more." if len(hits) > limit else "",
            "lines": [{"id": sid, "text": text} for sid, text in hits[:limit]]}

def collocates(word, genre=None, window=3, min_count=3, top=10):
    """Words that occur near `word` more often than chance, ranked by PMI."""
    word = word.lower()
    near, total, n = Counter(), Counter(), 0
    for sid, g, s in INDEX:
        if genre is not None and g != genre:
            continue
        toks = [t.lower() for t in s if t.isalpha()]
        total.update(toks); n += len(toks)
        for i, t in enumerate(toks):
            if forms_match(t, word):
                near.update(toks[max(0, i - window):i] + toks[i + 1:i + 1 + window])
    hits = sum(near.values())
    scored = [(math.log2((c / hits) / (total[w] / n)), w, c)
              for w, c in near.items() if c >= min_count]
    return {"word": word, "window": window, "min_count": min_count,
            "collocates": [{"word": w, "together": c, "pmi": round(p, 1)}
                           for p, w, c in sorted(scored, reverse=True)[:top]]}

def define(word):
    senses = wordnet.synsets(word)
    if not senses:
        return {"error": f"{word!r} is not in the dictionary. Try its base form."}
    return {"word": word, "senses": [{"pos": s.pos(), "gloss": s.definition()} for s in senses[:8]]}
