Answer to last lesson's question. You cannot paste five thousand pages into a prompt, and Lesson 7 showed you would not want to. A program has to score every passage for relevance to the sentence in hand and keep the top few. That scoring-and-selecting step is retrieval, and it is Lesson 7's "select" move, automated.

1. The retrieval problem

Given a query and a large collection of documents, return the few documents most useful for answering the query, quickly. Every search engine solves this. In AI engineering it sits in front of a model: retrieved passages are placed in the context, and the model answers from them. The pattern is called retrieval-augmented generation, or RAG, and Lesson 17 assembles it.

The scoring function has to be cheap, because it runs against the whole collection. So the standard design turns every document into a vector ahead of time, turns the query into a vector when it arrives, and compares vectors. Everything in this lesson is a choice of how to build those vectors.

2. The oldest idea: count the words

Represent a document by which words it contains and how often, ignoring their order. This is the bag of words. Put every document's counts side by side and you have a term-document matrix: one row per vocabulary word, one column per document.

You have seen this object before. In Lesson 2 a word was described by the words around it. Here a word is described by the documents it appears in, and a document by the words in it. It is the distributional idea again, at a larger scale. Because most words are absent from most documents, nearly every entry is zero, so these are sparse vectors.

3. Not all words are equal: tf-idf

Raw counts have an obvious flaw. The appears everywhere and says nothing; dual appears in few documents and says a lot. The classic fix weights each word by two factors:

  • Term frequency (tf): how often the word occurs in this document. More occurrences, more relevant.
  • Inverse document frequency (idf): how rare the word is across the collection, log(N / df), where N is the number of documents and df is how many contain the word. A word in every document gets log(1) = 0 and vanishes.

The weight is their product, and documents are ranked by the cosine between the query's vector and each document's, exactly as in Lesson 2.

4. The vocabulary mismatch problem

The last experiments show the central weakness of word matching. The document about the plural is the right answer to more than one, and it scores zero, because it shares no word with the query. People describe the same thing in different words far more often than intuition suggests. A searcher who does not already know the term of art cannot find the page that defines it.

The same wall appears as:

  • Synonyms and paraphrase: plural / more than one.
  • Morphology: write / wrote; كتاب / وكتابها. Lesson 15 deals with this.
  • Language: an Arabic query against English text shares no words at all. Lesson 18 deals with this.

5. Dense retrieval

Lesson 2 ended with embedding models: networks that read a whole passage and return one dense vector, placing passages with similar meanings near each other. Use that vector in place of word counts and you have dense retrieval:

documentsoffline, once
→
embedone vector each
→
indexstored vectors
queryat request time
→
embedsame model
→
nearestby cosine
→
top k

Because query and document are embedded separately by the same model, this design is called a bi-encoder. Its great advantage is that all the expensive work on documents is done once. At query time you embed one short text and compare numbers.

For a few thousand vectors, comparing the query with every one is instant, and that is what you will do. For millions, systems use an approximate nearest neighbour index, which finds almost all of the closest vectors while looking at a small fraction of them. Vector databases are, at heart, that index plus storage. You do not need one until brute force is too slow, and you should measure before deciding it is.

Checkpoint

Lab: two retrievers over a real corpus

Time: 75 minutes. The corpus for this phase is the documentation of Universal Dependencies itself: clone the UniversalDependencies/docs repository from GitHub and use the Markdown files under its _u-pos, _u-feat and _u-dep folders (if the layout has changed, pick any folders of guideline pages). You may use a different corpus you care about, as long as it has at least a hundred pages. pip install numpy sentence-transformers.

import glob, math, re
import numpy as np
from collections import Counter
from sentence_transformers import SentenceTransformer

paths = sorted(glob.glob("docs/_u-*/*.md"))
docs = [open(p, encoding="utf-8").read() for p in paths]
tokenize = lambda s: re.findall(r"\w+", s.lower())

# --- sparse: tf-idf from scratch ---
df = Counter(t for d in docs for t in set(tokenize(d)))
idf = {t: math.log(len(docs) / n) for t, n in df.items()}
vocab = {t: i for i, t in enumerate(idf)}

def tfidf(text):
    v = np.zeros(len(vocab))
    for t, n in Counter(tokenize(text)).items():
        if t in vocab:
            v[vocab[t]] = n * idf[t]
    norm = np.linalg.norm(v)
    return v / norm if norm else v

S = np.array([tfidf(d) for d in docs])

# --- dense ---
model = SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")
D = model.encode(docs, normalize_embeddings=True, show_progress_bar=True)

def search(query, k=5):
    sparse = np.argsort(-(S @ tfidf(query)))[:k]
    dense = np.argsort(-(D @ model.encode(query, normalize_embeddings=True)))[:k]
    return [paths[i] for i in sparse], [paths[i] for i in dense]

for q in ["dual number", "a word for exactly two things", "SCONJ",
          "how do I tag the verb to be"]:
    s, d = search(q)
    print(q, "\n  sparse:", s[:3], "\n  dense: ", d[:3])
  1. Write ten queries of your own: five using the guidelines' exact terms, five describing the same things in everyday words. Run all ten through both retrievers.
  2. For each query, mark whether the right page is in each retriever's top three. Fill in a two-by-two table: term queries and everyday queries, sparse and dense.
  3. Which words have the five lowest and five highest idf values in this corpus? Do they match your intuition about informative words?
  4. Try one query in Arabic, for example ما هو المثنى؟. What does each retriever return? Keep the result for Lesson 18.
  5. These pages vary greatly in length, and the embedding model reads only a limited number of tokens of each. Note any long page that dense retrieval misses. Lesson 14 is about that.
