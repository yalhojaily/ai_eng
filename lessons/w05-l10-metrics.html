Answer to last lesson's question. Nouns are the most common class, typically somewhere between a sixth and a third of all words depending on the language and the text. So the tagger that answers NOUN every time is right that often while knowing nothing. Any accuracy figure is meaningless until you know what doing nothing would have scored. That do-nothing score is called a baseline.

1. Accuracy, and its blind spot

Accuracy is the share of items answered correctly. It is simple, and for balanced tasks it is fine. Its weakness is that every item counts equally, so frequent classes dominate. A system can be excellent on NOUN, VERB and PUNCT, hopeless on AUX and SCONJ, and still post a high accuracy, because the classes it fails on are rare. Those rare classes are often the ones your application cares about.

Two habits fix most of the damage. Always report accuracy next to a baseline. And always break the result down by class, which is what the rest of this lesson builds.

2. The confusion matrix

A confusion matrix is a table of counts. Rows are the gold answer, columns are what the system said. Every item lands in exactly one cell. The diagonal holds the correct answers; everything off the diagonal is an error, and its position says which error.

3. Precision and recall

For any one class, there are two different ways to be good, and they answer different questions. Take AUX.

  • Precision: of the words the system called AUX, how many really are? It falls when the system cries AUX too often.
  • Recall: of the words that really are AUX, how many did the system find? It falls when the system misses them.

In matrix terms: precision divides the diagonal cell by its column total; recall divides it by its row total. The pieces have names. A true positive is a correct AUX. A false positive is something wrongly called AUX. A false negative is a real AUX that was called something else.

precision = TP / (TP + FP)        recall = TP / (TP + FN)

F1 = 2 × precision × recall / (precision + recall)

The two pull against each other. A system that says AUX only when certain has high precision and poor recall. One that says AUX at the slightest hint has the reverse. F1 combines them into one number that is high only when both are: it is their harmonic mean, which sits close to the lower of the two.

Which matters more depends on the cost of each mistake. A filter that removes harmful content should favour recall: missing one is worse than a false alarm. A system that auto-corrects text should favour precision: a wrong correction is worse than none.

4. One number for many classes

With seventeen tags you have seventeen F1 scores. There are two standard ways to average them:

  • Macro-F1: the plain mean of the per-class F1 scores. Every class counts the same, however rare. A system that ignores a rare class is punished hard.
  • Micro-averaging: pool all the counts first, then compute. Every item counts the same. For a task with exactly one label per item, micro-F1 equals accuracy.

Report accuracy and macro-F1 together. When they are close, the system is even across classes. When accuracy is much higher, some class is being neglected, and the per-class table shows which.

5. A complication from linguistics: alignment

Everything above assumed you can line up predictions with gold answers one to one. For English tagging you nearly always can. For Arabic you often cannot, because the system must first decide where the words are. If gold has و | كتاب | ها and the system produced و | كتابها, there are three gold words and two predictions, and no position-by-position comparison is possible.

Two ways to handle it:

  • Simple and honest: score tags only on sentences whose segmentation matches gold exactly, and report the segmentation match rate as its own number. You will do this in the lab.
  • Standard in research: align words by their character positions in the original text, and count a predicted word as correct only if it covers the same characters as a gold word and has the same tag. Segmentation errors then lower precision and recall directly. The official UD evaluation script works this way.

Either way the principle is the one from Lesson 8: measure each stage of a pipeline separately, or an early error hides inside a later number.

6. From numbers to fixes: error analysis

Metrics tell you where the system fails. They do not tell you why. For that you read the errors, and this is where knowing linguistics pays. The routine:

  1. Sort the off-diagonal cells of the confusion matrix by size. Take the largest.
  2. Pull twenty examples from that cell and read each in its sentence.
  3. Give each a short label for its cause. Typical ones: guideline convention unknown, genuinely ambiguous, gold looks wrong, segmentation upstream, rare word.
  4. Count the labels. The biggest group is your next prompt change, and the "gold looks wrong" group is the ceiling on what any change can achieve.

This is Lesson 5's iteration loop with a measuring instrument attached. A category with fifteen errors and a clear cause is worth an afternoon. A category with two is not.

Checkpoint

Lab: score your annotator

Time: 90 minutes. Use the development files from Lesson 9 and the annotator from Phase 2.

import json
from collections import Counter

def read(path):
    return [json.loads(line) for line in open(path, encoding="utf-8")]

def score(pairs):
    """pairs: list of (gold_tag, predicted_tag)"""
    conf = Counter(pairs)
    tags = sorted({t for pair in pairs for t in pair})
    accuracy = sum(g == p for g, p in pairs) / len(pairs)
    rows = []
    for t in tags:
        tp = conf[(t, t)]
        fp = sum(conf[(g, t)] for g in tags if g != t)
        fn = sum(conf[(t, p)] for p in tags if p != t)
        prec = tp / (tp + fp) if tp + fp else 0.0
        rec = tp / (tp + fn) if tp + fn else 0.0
        f1 = 2 * prec * rec / (prec + rec) if prec + rec else 0.0
        rows.append((t, prec, rec, f1, tp + fn))
    macro_f1 = sum(r[3] for r in rows) / len(rows)
    return accuracy, macro_f1, rows, conf

def evaluate(items, annotate_fn):
    pairs, skipped, errors = [], 0, []
    for it in items:
        pred = annotate_fn(it["text"])
        if [p["form"] for p in pred] != [g["form"] for g in it["tokens"]]:
            skipped += 1                       # segmentation differs from gold
            continue
        for g, p in zip(it["tokens"], pred):
            pairs.append((g["upos"], p["upos"]))
            if g["upos"] != p["upos"]:
                errors.append((g["form"], g["upos"], p["upos"], it["text"]))
    return pairs, skipped, errors

items = read("data/en_dev.jsonl")
pairs, skipped, errors = evaluate(items, lambda s: annotate(s, SYSTEM))
accuracy, macro_f1, rows, conf = score(pairs)
print(f"accuracy {accuracy:.3f}  macro-F1 {macro_f1:.3f}  "
      f"segmentation match {1 - skipped / len(items):.2f}")
for t, prec, rec, f1, n in rows:
    print(f"{t:6} P {prec:.2f}  R {rec:.2f}  F1 {f1:.2f}  n={n}")
print([(k, v) for k, v in conf.most_common() if k[0] != k[1]][:5])
